# zookeeper: how this example ran, and how to run it by hand

Generated by the test harness during the run of `ZooKeeperFrontDoorsTest` on 2026-10-04. Every command, file and step below is what that run used; machine paths are replaced by `$REPO` (the repository root), `$TMPDIR`, `$HOME` or the install variables (`$AEGIS_KNOX_HOME` and so on), and secrets are shown by name only. Ports are the free ports that run picked.

The test that drives it: [`ZooKeeperFrontDoorsTest.java`](../../../examples/aegis-validation/src/test/java/io/github/vaquarkhan/aegis/validation/ZooKeeperFrontDoorsTest.java).

## 1. The engine

The test started one engine process, the way the engine's own launcher script starts it:

Process 1:

```text
java \
  -cp \
  <the jars listed in $REPO/examples/aegis-validation-zookeeper-server/target/server.classpath> \
  org.apache.zookeeper.server.ZooKeeperServerMain \
  engine/zoo.cfg
```

`$REPO/examples/aegis-validation-zookeeper-server/target/server.classpath` is written by the `-Preal-engines` build of that module: the engine's jars, at the version its `pom.xml` names, as Maven resolved them. With a binary distribution, use its own `lib/` instead.

The engine's own configuration file, as the test wrote it: [`engine/zoo.cfg`](engine/zoo.cfg).


The data the scenario works on (topics, tables, queues, jobs) is created by the test's `@BeforeAll` method against the engine's own API, outside Aegis; see the test source.

## 2. Without Knox: Aegis's own server

The file: [`aegis/own-host.yaml`](aegis/own-host.yaml), exactly what this door loaded: the shipped adopter profile with the engine address and egress network substituted, plus a `host:` section (loopback listener on a free port, one static bearer token per person, read from the environment).

Environment the gateway reads:

- `AEGIS_SIGNING_KEY`: approval signing key, at least 32 bytes
- `AEGIS_VALIDATION_TOKEN_APPROVER`: bearer token for that persona, at least 16 characters
- `AEGIS_VALIDATION_TOKEN_OPERATOR`: bearer token for that persona, at least 16 characters
- `AEGIS_VALIDATION_TOKEN_OUTSIDER`: bearer token for that persona, at least 16 characters
- `AEGIS_VALIDATION_TOKEN_READER`: bearer token for that persona, at least 16 characters
- `AEGIS_ZOOKEEPER_DIGEST`: credential the adopter YAML reads

Start it from the repository root after `mvn -B -Preal-engines -DskipTests install`:

```bash
# this profile uses a source plugin: put it and its jars on the classpath (same jars as Knox ext/, below)
java -cp "aegis-gateway/target/aegis-gateway-2.0.0-SNAPSHOT-all.jar;<plugin jars>" io.github.vaquarkhan.aegis.gateway.Main \
  --config examples/adopters/zookeeper/aegis/own-host.yaml
```

## 3. With Knox: Aegis inside Apache Knox 3.0.0

The files: [`aegis/knox-aegis.yaml`](aegis/knox-aegis.yaml), the same adopter profile with no `host:` section (Knox is the host), and [`aegis/knox-topology.xml`](aegis/knox-topology.xml), the Knox topology: ShiroProvider against Knox's demo LDAP, Default identity assertion with `group.principal.mapping` (person to adopter groups), `AclsAuthz` on the route, and the `AEGIS_MCP` service.

Steps, in the order the test performed them on a stock Knox 3.0.0 (`$AEGIS_KNOX_HOME`, from `examples/adopters/knox/install-knox.ps1` or `.sh`):

```bash
cd $AEGIS_KNOX_HOME
# 1. the Aegis extension
cp $REPO/aegis-knox3-extension/target/aegis-knox3-extension-2.0.0-SNAPSHOT-knox-bundle.jar ext/
# 1b. the source plugin: copy each jar marked ADD in results/knox-ext-plugins.log to ext/aegis-plugin-<jar>
# 2. a master secret and a TLS certificate for localhost
java -jar bin/knoxcli.jar create-master --master <a master secret of your choice>
java -jar bin/knoxcli.jar create-cert --hostname localhost
# 3. conf/gateway-site.xml: set gateway.port (the test used a free port) and gateway.host 127.0.0.1
# 4. the Aegis configuration and the topology
mkdir -p conf/aegis && cp $REPO/examples/adopters/zookeeper/aegis/knox-aegis.yaml conf/aegis/zookeeper.yaml
cp $REPO/examples/adopters/zookeeper/aegis/knox-topology.xml conf/topologies/aegis-zookeeper.xml   # then replace ${KNOX_HOME} in it
# 5. Knox's demo LDAP (port 33389) and the gateway
java -jar bin/ldap.jar conf &
java -jar bin/gateway.jar
```

Environment for the gateway process (the Aegis configuration reads it):

- `AEGIS_SIGNING_KEY`: approval signing key, at least 32 bytes
- `AEGIS_ZOOKEEPER_DIGEST`: credential the adopter YAML reads

The route: `https://localhost:<gateway.port>/gateway/aegis-zookeeper/aegis-mcp/v1/mcp`; the admin API is `.../aegis-mcp/v1/admin/`. Knox demo LDAP users are in `conf/users.ldif`; supply that installation's demo credentials through your terminal or IDE, never in a committed configuration.

  -u <knox-demo-user>:<knox-demo-password> \
