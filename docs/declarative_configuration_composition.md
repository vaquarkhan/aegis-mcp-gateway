# Declarative Configuration Composition

Aegis supports deterministic, build-time composition of **gateway-level governance** (`gateway.yaml`) and **adopter-specific source integrations** (`adopter.yaml`) into a single effective gateway configuration file.

This separates platform security and runtime concerns from individual data-source onboarding while ensuring the deployed configuration remains a single validated YAML artifact.

---

## Two-Layer Model

```text
gateway.yaml (Platform / Governance)  ──┐
                                        ├──► aegis-gateway --compose ──► effective <adopter>.yaml
adopter.yaml (Source / Scope / Hooks) ──┘
```

| Layer | Maintained By | Allowed Top-Level Keys |
| :--- | :--- | :--- |
| **`gateway.yaml`** | Platform / Security Team | `server`, `state`, `auth`, `security`, `observability`, `governance`, `rateLimits`, `guardrails`, baseline `policy` |
| **`adopter.yaml`** | Data / Adapter Team | `sources`, source-scoped `policy.rules`, source-scoped `hooks` |
| **Composed Output** | Build / CI Artifact | Normalized, deterministically ordered YAML with an Apache 2.0 header and `effectiveConfigHash` |

---

## CLI Reference

Configuration composition is invoked through the `aegis-gateway` uber-jar:

```bash
java -jar aegis-gateway/target/aegis-gateway-2.0.0-SNAPSHOT-all.jar \
  --compose \
  --gateway-config <path-to-gateway.yaml> \
  --adopter <path-to-adopter.yaml> \
  --out <path-to-output.yaml> \
  [--check]
```

### Flags

| Flag | Required | Description |
| :--- | :---: | :--- |
| `--compose` | Yes | Runs build-time configuration composition instead of starting the gateway runtime. |
| `--gateway-config <path>` | Yes | Path to the platform governance YAML file. |
| `--adopter <path>` | Yes | Path to an adopter source YAML file. Repeat `--adopter` to compose multiple adopters into one gateway. |
| `--out <path>` | Yes | Target path for the composed YAML file. Must not resolve to any input file. |
| `--check` | No | Verifies that `--out` matches the deterministic composition output without writing to disk; exits non-zero on drift. |

---

## Composition Rules & Guarantees

1. **Strict Field Ownership**
   Adopter files may only declare source integration keys (`sources`, source-scoped `policy.rules`, and source-scoped `hooks`). Attempting to override gateway-owned sections (`server`, `state`, `auth`, `security`, `observability`, `governance`, `rateLimits`, or global `guardrails`) in an adopter file fails composition immediately.
2. **Cross-Adopter Collision Detection**
   When multiple `--adopter` files are supplied, duplicate source names, tool names, or hook names across adopters are rejected.
3. **Source-Scoped Policy & Hooks**
   Hooks and policy rules defined inside an `adopter.yaml` are bound to the scopes of the sources declared in that adopter file rather than applied globally.
4. **Schema-Aware Path Resolution**
   Relative filesystem paths (such as TLS keystores/truststores, policy files, or Derby state directories) are resolved relative to the directory of the YAML file that declared them and re-relativized to the parent directory of `--out`. Non-filesystem URIs (`http://`, `https://`, `vault://`, `jdbc:...`) are preserved unchanged.
5. **Atomic Output & Input Protection**
   Composed configurations are written atomically via temporary file creation and `ATOMIC_MOVE`. Composition refuses to overwrite any input file (`--gateway-config` or `--adopter`).
6. **License & Hash Provenance**
   Every generated file includes the standard Apache 2.0 license header followed by `# Generated by Aegis ConfigComposer` and `# effectiveConfigHash: sha256:...`.

## Pilot Example: Apache Hive

The Hive adopter layout demonstrates the two-layer pattern:

```text
examples/adopters/hive/aegis/
├── gateway.yaml     # Shared gateway server, auth, state, and baseline governance
├── adopter.yaml     # Hive HS2 JDBC source, SQL guardrails, and Hive-scoped hooks
└── canonical.yaml   # Reference snapshot matching adopters/configurations/adapters/hive/hive.yaml
```

### Regenerate `hive.yaml`
```bash
java -jar aegis-gateway/target/aegis-gateway-2.0.0-SNAPSHOT-all.jar \
  --compose \
  --gateway-config examples/adopters/hive/aegis/gateway.yaml \
  --adopter examples/adopters/hive/aegis/adopter.yaml \
  --out adopters/configurations/adapters/hive/hive.yaml
```

### CI Drift Check
CI enforces that `adopters/configurations/adapters/hive/hive.yaml` stays synchronized with its source layers:

```yaml
- name: Check composed Hive configuration is current
  run: |
    java -jar aegis-gateway/target/aegis-gateway-2.0.0-SNAPSHOT-all.jar \
      --compose \
      --gateway-config examples/adopters/hive/aegis/gateway.yaml \
      --adopter examples/adopters/hive/aegis/adopter.yaml \
      --out adopters/configurations/adapters/hive/hive.yaml \
      --check
```

## Onboarding a New Adopter

1. Create `examples/adopters/<name>/aegis/gateway.yaml` (or reuse a shared gateway baseline) and `examples/adopters/<name>/aegis/adopter.yaml` with the Apache 2.0 license header.
2. Materialize `adopters/configurations/adapters/<name>/<name>.yaml` via `--compose`.
3. Add a `--check` verification step for `<name>.yaml` in CI.
