BOUNDARY

What is under review.

Aegis is reviewed as the MCP decision plane after host identity is established and before a source presents a backend credential. Own-host and Knox are front-door choices; both feed the same governance engine.

In scope

Tool, resource, prompt, and completion calls; catalog pinning; approvals and receipts; egress; audit; hooks; output bounds; declarative HTTP and typed sources as capability only.

Out of scope

Model training and RAG poisoning, agents that never call Aegis, backend-internal ACLs beyond the gateway credential, discovery of shadow MCP servers off this path, and host OS or SIEM product choice.

Cross-zone rule: a call may not present a backend credential until the governance core has written ALLOW_INTENT (or denied). Caller tokens never enter the backend zone for protected backends.

STRIDE AND ABUSE

Named abuse scenarios with expected denials.

The threat model elaborates STRIDE per zone into abuse cases TM01 to TM10. Each case states preconditions, attacker goal, expected gateway outcome, and the S-property that owns the proof.

TM01 Prompt-injected destructive call

Untrusted context steers a privileged caller. Expect policy, approval, and receipt binding before any backend write.

TM02 Tool poisoning / rug-pull

A changed tool definition is quarantined; prior approvals and receipts do not bind the new digest. With a signed serverCatalog, only the reviewed pins can bind and run-time acceptance is refused.

TM03 Confused deputy

Inbound caller tokens are not forwarded to protected backends; token exchange is egress-checked and subject-bound.

TM04 SSRF via nested URL

Nested HTTP(S) arguments and DNS answers pass egress classification; redirects are not followed.

TM05 READ carries a mutate

Classification, sql-readonly hooks, and least-privilege credentials contain the call; fail closed on ambiguity.

TM06 Self-approval

Requester cannot approve under an alternate spelling; delegated identities cannot approve.

TM07 Shadow MCP bypass

External residual: Aegis cannot govern a path that never reaches it. Network inventory remains operator work. For servers behind Aegis, a signed serverCatalog limits which may start, and a break-glass order can contain one during an incident.

TM08 to TM10

Post-delivery disclosure, supply-chain pin trust, and host CSRF/Origin checks are covered in the full model.

OWASP MCP TOP 10

Coverage is not a claim of elimination.

MCP01 to MCP03Strong gateway controls for tokens, privilege scope, and changed tool definitions when the first pin is trusted.
MCP04 and MCP05Partial supply-chain and command-execution coverage; release controls and runtime sandboxing remain outside Aegis.
MCP06Prompt-injection screening is heuristic. Typed scope and independent approval are the durable safeguards.
MCP07 and MCP08Strong authentication/authorization and local audit evidence; IdP operations and SIEM remain deployment work.
MCP09Shadow servers cannot be discovered by a gateway that is not on their path. Behind Aegis, a signed server catalog limits which configured servers may start.
MCP10Caller-filtered discovery helps, but clients can retain or disclose received data.

PROMISES

Security properties S1 to S31.

Each property names the enforcing class and the test that must stay green. Breaking one is treated as a vulnerability. Highlights for reviewers:

S1 to S4Identity required, JWT rules, no token passthrough, default deny.
S5 to S7Approval, dry-run receipt, hash-chained audit intent.
S8 to S11Egress, catalog pin, request agreement, bounded redacted output.
  • S17 / S28: admin and audit-verify APIs are group-scoped; CSRF Origin checked; verify reveals only true/false.
  • S21 / S26: own-host route groups and optional OAuth scopes run before body buffering; per-tool actionScopes need exact verified JWT scopes before policy.
  • S22: a signed serverCatalog decides at startup which servers may start; a break-glass order can only contain them.
  • S27: Knox packaging boundary; own-host jar contains no Knox classes.
  • S29 / S31: token exchange and A2A card endpoint trust fail closed.

RESIDUAL RISK

What operators still own.

  • Prompt injection and redaction remain heuristic; approvals and least privilege are the durable controls.
  • First catalog pin trust, plugin provenance, and release scanning are release-process work.
  • Network policy must prevent shadow MCP paths that never hit Aegis.
  • Backend ACLs and credential scope remain required under every tool class.
  • Clients can retain or disclose results after a governed allow.

Report vulnerabilities privately via a GitHub security advisory. Do not open a public issue for an unfixed vulnerability.
